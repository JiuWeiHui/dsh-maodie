# 耄耋 (maodie)

DSH 桌面端（Electron 客户端）的常驻挂件：一只可以拖动、缩放、放到屏幕任何位置的猫。
点一下哈气，连点三下它会打你并炸出粒子；一轮对话结束时提醒你；随时看峰谷价和余额。

> 「耄耋」这个名字只出现在设置窗口里。

## 它做什么

| 部分 | 行为 |
| --- | --- |
| **猫** | 拖动移动 · 滚轮或角柄缩放（0.3–3.5 倍）· 位置/大小持久化 · 贴左侧自动水平镜像 · 按压回弹 |
| **点击** | 切哈气图 + 播声音 + 冒气泡 |
| **连点三下** | 用**哈气图**摇晃 + 光标处粒子爆炸 + 特殊音效 + 冒气泡（不额外需要攻击图） |
| **气泡** | 峰价/谷价 + 距切换倒计时 + DeepSeek 余额 + 今日已用 + **本次消耗**（当前会话花了多少） |
| **本次消耗** | 以「会话开始时的余额」为基准做余额差，并累计真实 usage（input + cacheRead + output）；换会话自动重置，跨 Host 重启保留 |
| **外观** | 内置两张猫图之外可以**自己上传外观图**：给「常态 / 哈气」各挑一张；PNG 透明底最好，插件按不透明区域的包围盒自动对齐，两张尺寸不同也不跳 |
| **戳破气泡** | 气泡缩回关闭，**同时立刻掐断正在播的音效**（不用等它播完） |
| **任务完成** | 原生窗口闪烁/还原前台 → 系统通知 → 标签页标题闪烁 → 声音 → 猫表演 + 气泡（逐项开关，**任何一环不可用都自动降级，绝不静默**） |
| **声音** | 槽位数量不限、可增删改名排序；每个槽位绑定一个触发器、可勾选任意多个素材、随机抽/顺序轮播/全部播、冷却、循环；**所有试听都能暂停** |
| **音频裁剪器** | 波形 + 滚轮缩放（1–50 倍）+ 双边界拖动 + 毫秒输入 + 选区循环试听（**同一个按钮开关**）+ 首尾淡入淡出（**可开关**，时长可调）+ 音量归一化 + 一键去首尾静音 + 导出 WAV |
| **闹钟** | 每天固定时间 / 一次性；按**本机时间**判定；DSH 开着就检查；到点循环播放，手动停；设置里有**立即测试整条链路** |
| **峰谷** | 工作日 9:00–12:00、14:00–18:00 = 高峰（北京时间口径）；**周六周日与法定节假日全天谷价** |
| **设置** | 右键猫弹出独立设置窗口（外观 / 声音 / 提醒 / 峰谷 / 关于） |

### 默认声音槽位

| 槽位 | 触发器 | 默认素材 | 策略 |
| --- | --- | --- | --- |
| 提示音 | 猫·点击 | 哈气（m4a） | 随机 |
| **特殊提示音** | 猫·连击 | **空**（自己去素材库勾） | 随机 |
| 任务完成音 | 任务完成 | **全部 4 个 MP3** | 随机 |
| 闹钟音 | 闹钟到时 | **全部 4 个 MP3** | 随机 + **循环** |

> 哈气是 m4a，不参与「全部 MP3」，它单独绑在猫·点击上。四个槽位都是普通槽位，可改可删。

**任务完成**与**闹钟**都会冒气泡：任务完成气泡带你的通知文案，闹钟气泡显示
**你在设置里填的提示文字**（默认「起床」）+ 时刻。
**戳破任意气泡都会立刻掐断正在播的声音**，包括循环播放的闹钟音；气泡上的
「戳一下关掉（会同时掐断声音）」就是这句承诺。

## 安装 / 热加载（DSH 0.2 桌面版）

> **旧版 README 里那套「手改 `~/.dsh/profiles/desktop/package.json` 再重启」已经过时，不要再用。**
> 现在官方路径是 **plugin_manager 服务**（应用内的 Plugins 页面 / 会话里的 `plugin_manager` 工具），
> 它负责 pnpm 安装 + 写 bundle 选择 + 让 Loader 重新对账，**安装这一步是热生效的，不需要重启**。

### 方式 A：让 Agent 装（本插件就是这么装的）

```
plugin_manager { action: "install_bundle",
                 target: "link:C:/Users/rennanchuan/Desktop/dsh-maodie" }
```

`target` 用 `link:<插件的绝对路径>`。装完 `~/.dsh/profiles/desktop/package.json` 会变成：

```json
{
  "dependencies": { "maodie": "link:C:/Users/rennanchuan/Desktop/dsh-maodie" },
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "maodie"] } }
}
```

顺便：`node_modules/maodie` 会是一个指向上面的目录的 **junction**，所以改仓库里的代码就是改线上代码。

### 方式 B：在应用里点

侧栏 → **Plugins → Add plugin** → 填插件的**绝对路径** → 安装。

### 方式 C：CLI

`dsh plugin --profile desktop …` 仍然会被拒绝：desktop profile 由桌面端独占管理。

### 装完之后要做什么

| 改了什么 | 怎么生效 |
| --- | --- |
| 前端 `assets/maodie.js` | **不用重启**：前端脚本自带版本对齐，Host 版本一变就自动刷新页面（Host 每次请求都重新读盘下发脚本） |
| Host `lib/index.js` 的业务逻辑 | **需要重启一次桌面端**（见下，已实测过每一条热重载路径） |
| 往 index 注入表里新增/删除行 | **需要重启一次桌面端**（注入表只在 Host 启动时收集一次） |
| 开关 `include:maodie`、改 profile patch | plugin_manager 直接热生效（`application: "applied"`） |

**为什么 Host 代码必须重启**（2026-10 实测，不是没试）：

| 尝试过的办法 | 结果 |
| --- | --- |
| 直接改 `lib/index.js`（含 append、替换文件） | ❌ 不重载 —— desktop profile 的 HMR 只盯配置文件，`root: []` 不盯模块源码 |
| 手改 `~/.dsh/profiles/desktop/cordis.patch.yml` | ❌ 不生效 —— 这个 profile 没有 `patchReload: live`，手改的 patch 只在启动时读 |
| `plugin_manager` 关掉再打开 `include:maodie` | ⚠️ 插件**确实重新挂载**（`/maodie/diag` 会先 404 再回来，`helloCount` 归零），但 Node 的 ESM 缓存按 URL 命中，拿到的是**同一个旧模块** |
| 给该行换成带版本 query 的 `file://…/lib/index.js?v=1.2.1` 说明符 | ❌ 行模块说明符的改动不会被热应用（同上：patch 不热读） |

结论：**Host 模块只能靠新进程**，也就是「退出并重开一次 DeepSeek Harness」。
dsh 自己的文档写的也是这句：**「包替换需要重启进程才能拿到新的 JS 模块世代」**。
前端不受影响：`MAODIE_VERSION` 与 `init.json` 里的 Host 版本不一致时，前端会自己
`location.reload()`（`sessionStorage` 防循环），所以**以后只改前端不需要任何手动操作**。

### 怎么确认「屏幕上跑的是哪一版」

踩过这个坑：连着改了几轮，页面却一直跑着改动之前的脚本，于是**同一个 bug 反复出现，
看起来像「越修越坏」**。现在有三个地方能一眼看出来：

| 看哪里 | 怎么读 |
| --- | --- |
| **设置窗口标题** | 直接写着 `耄耋 · 设置（前端 1.2.5 · Host 1.2.5）`；**两个数字不一样 = 其中一个还没换新** |
| 设置 → 关于 | 第一行 `前端 x · Host y`（同上） |
| `/maodie/diag` | `plugin` = Host 版本，`frontend.report.version` = **页面真正在执行的前端版本** |

**加载新版本的两条路**：

- **只改了前端**（`assets/maodie.js`）：右键猫 → **关于 → 「从磁盘重载」**（或者刷新页面）。
  脚本是按请求从磁盘读的，所以重载后立刻是新版，不用重启桌面端。
  此时标题会显示「前端 1.2.5 · Host 1.2.2」这类组合 —— 前端换新了、Host 还没有。
- **改了 Host**（`lib/index.js`）：只能**退出并重开一次** DeepSeek Harness（原因见上表）。

### 「猫不出现」排查顺序

1. `http://127.0.0.1:<port>/maodie/diag` —— 看两件事：
   - `indexInjection.rowsInTable ≥ 1`：Host 侧确实往注入表里推了行 → 注入机制没问题；
   - `frontend.booted`：前端脚本真的在页面里跑过（起来后会 POST 一次 `/maodie/hello`）。
     如果是 `false` 而 `rowsInTable ≥ 1`，就是**注入表还是上一代**（重启桌面端即可）。
2. `http://127.0.0.1:<port>/maodie/doctor` —— 页面内的自检，会实际请求各条路由。
3. 主窗口 F12 看 Console 红色报错。

### 卸载

```
plugin_manager { action: "remove_bundle", target: "maodie" }
```

## 素材

内置素材随包发布在 `assets/`：

| 文件 | 用途 |
| --- | --- |
| `cat-idle.png` | 常态（1248×2048，透明底） |
| `cat-hiss.png` | 哈气（1280×1760，透明底；连点三下也用它） |
| `sound/hiss.m4a` | 哈气音（1 秒） |
| `sound/jiao.mp3` | 叫一叫（55 秒） |
| `sound/dahuoji.mp3` | 打火基（2 分 03 秒） |
| `sound/qichuang.mp3` | 起床哈（1 分 30 秒） |
| `sound/lanlian.mp3` | 蓝莲哈（4 分 33 秒） |

**两张猫图的尺寸不一样**，切换姿态时不能直接用画布对齐。插件按各自的 **alpha 包围盒**换算：

| 图 | 画布 | 猫的实际范围 |
| --- | --- | --- |
| 常态 | 1248×2048 | 1051×1853（x 169, y 147） |
| 哈气 | 1280×1760 | 1015×1607（x 209, y 152） |

规则：以常态的包围盒为**场景蓝本**；每张图按同一个"每像素容器宽"渲染，包围盒**水平居中**、
**底边对齐**，高度差的一半作为垂直补偿。这样切换时既不会缩放跳变，也不会上下错位。
换图时改 `assets/maodie.js` 里的 `POSE_SRC`（四个数字：bboxW / bboxH）即可。

**用户自己上传的素材**落在 `~/.dsh/maodie/sounds/`，索引在 `sounds/index.json`；内置素材不可删除。

## 桌面端注入（2026-10 迁移的关键）

0.2 的桌面版把主窗口跑在自定义协议 `dsh-app://app/` 下，这对老插件是**致命变化**：

| 事实（读 `app.asar` 得到） | 后果 |
| --- | --- |
| 主窗口的 `index.html` 由 Electron 壳 `serveWebDocument()` **直接从 asar 里的 dist 读**，不走 `ctx.webServer.renderIndex()` | 老的 `webServer.tapIndex()` 注入对主窗口**完全无效** |
| 非静态路径（不是 `/`、`/index.html`、`/assets/*`）由 `dsh-app://` 协议处理器**转发给 Host**，并附上会话 cookie | 插件自己的路由仍然可达，前端用**相对路径**即可，不用猜端口 |
| 壳启动 Host 之后调一次 `ctx.webServer.collectIndexInjections()`，把整张**结构化注入表**经 `dshDesktopBoot.ready()` 交给页面里的解释器逐行执行 | 这才是官方注入通道；但**一张表只在 Host 启动时收集一次** |

所以本插件的做法是：监听 `webserver/index-inject`，往表里推一行

```js
{ kind: 'script-preload', src: '/maodie/maodie.js?v=1.1.0' }
{ kind: 'script-src', placement: 'head', src: '/maodie/maodie.js?v=1.1.0' }
```

- **浏览器直连**：`frontend-static` 渲染 index 时把这行渲染成真正的 `<script>`；
- **桌面端主窗口**：壳启动时收走这行，页面启动阶段 `await` 加载它。

脚本本体仍然由 Host 的 `/maodie/maodie.js` 路由**每次请求重新读盘**下发，
所以**前端改动只要刷新页面**，不用重装插件、不用重启。

> 老版本还有一套「在 Electron 主进程里包一层 `fs.promises.readFile`、改写那份
> `dsh-web-frontend/dist/index.html`」的补丁 —— 方向就错了：插件跑在 Electron 的
> **Node 子进程**（`--expose-internals dsh-desktop-host/lib/index.js`）里，
> 根本拿不到主进程的 `electron` 模块，探测结果是 `not-electron`。
> 这套代码已经删掉。

## 认证与安全（重要，踩过坑）

DSH 的 webserver 官方文档明确写着：**「不提供服务器级 TLS、认证或来源策略」**，
认证由每个 route owner 自己决定；服务器的默认姿态是**只绑 127.0.0.1（回环）**，
官方插件的静态资源本来就是公开的。

本插件最初给每条数据路由都套了 `ctx.connection.requestRejection` 信任栅栏，
结果在桌面端制造了死结：**主界面发起的请求不一定带签名会话 cookie**，于是
`/maodie/init.json` 恒返回 401，前端取不到数据 → 猫根本不出现。

（2026-10 迁移后的口径：桌面端主窗口发出的请求由 `dsh-app://` 协议处理器转发给 Host
并**自动附上会话 cookie**，所以相对路径 + `credentials: 'include'` 是可用的；
但默认仍然不设栅栏，理由见下表。）

现在改为：

| 设置 | 行为 |
| --- | --- |
| `security.requireAuth: false`（**默认**） | 数据路由不设栅栏。安全性由"只绑回环"保证：只有本机进程能访问 |
| `security.requireAuth: true` | 数据路由走 `ctx.connection.requestRejection`（Host/Origin + 会话 cookie 校验）；此时需要浏览器带上签名 cookie，否则 401 |

改法：编辑 `~/.dsh/maodie/state.json` 里的 `security.requireAuth`，或在前端设置里改后保存。

> 直接暴露在局域网的部署**务必**打开 `requireAuth`：把服务器绑到 `0.0.0.0` 时，
> 未设栅栏的路由对同网段是可读的。

## 今日已用的口径

- **金额**：只按**余额差**记账（当天首次观测为基准，之后取差值），与官方扣款口径最接近。
  不做 token 估算 —— 宁可显示「等待首次余额观测」，也不编一个数出来。
- **token**：按会话真实 usage 累计（`input + cacheRead + output`，`reasoning` 已含在 output 内）。
- 充值/退款导致余额上升时自动重置基准，不会出现负数。

## 峰谷与节假日

```
谷价 = 周六 || 周日 || 法定节假日 || 非高峰时段
高峰 = 工作日的 9:00–12:00 与 14:00–18:00
```

节假日数据三层保险：**本地缓存** → **联网拉取**（可在设置里关）→ **内置年度表**。
联网失败静默回落，绝不影响挂件运行。设置里还能按日期**手动覆盖**（优先级最高）。

## 原生能力与降级

桌面版确实是 Electron，但**插件跑在 Electron 拉起的 Node 子进程里**
（`--expose-internals …/dsh-desktop-host/lib/index.js`），**拿不到** `BrowserWindow` /
`Notification`。所以 Host 侧的探针结论在桌面端恒为不可用，实际提醒走前端：

```
（Host 侧原生） 不可用
        ↓ 自动降级
系统通知（渲染进程的 Chromium Notification）→ 标签页标题闪烁 → 声音 → 页面气泡
```

前端会在任务完成/闹钟时 `new Notification(...)`（点击回调里 `window.focus()`）+ 闪标题 +
播放声音 + 冒气泡，逐项可在设置里开关。`/maodie/init.json` 的 `native` 字段如实报告
Host 侧的探测结果，设置页的**原生能力状态**就是读它。

> 说明：浏览器/Electron 都**不允许**页面在无用户操作时抢焦点，所以"强制跳到前台"本身做不到；
> 能做到的是系统通知（点通知会跳回 DSH）+ 标题闪烁 + 声音。

## 本次消耗（当前会话）

「今日已用」和「本次消耗」是两个口径，别混：

| | 口径 | 什么时候重置 |
| --- | --- | --- |
| 今日已用 | 当天首次观测余额为基准的余额差 | 跨天（北京日期）或充值 |
| **本次消耗** | **当前会话**第一次观测余额为基准的余额差 + 真实 usage | 换会话（新 session id） |

- 金额只认**余额差**（与官方扣款口径最接近）；token 走会话真实 usage。
- 没有基准时如实显示「等待首次余额观测」，**不编数字**。
- 换会话自动重置；Host 重启不丢（存在 `~/.dsh/maodie/ledger.json` 的 `session` 字段里）。
- 显示位置：气泡里的「本次消耗」一行（可在**设置 → 外观**里关掉）、**设置 → 关于**里的明细。
- 通知文案模板里可以用 `{session}`（本次金额）、`{sessionTokens}`、`{turns}`。

## 自定义外观

**设置 → 外观 → 外观图**：

- 给「常态」「哈气」各选一张：内置的两张，或自己上传的。
- **＋ 选择图片**上传（PNG / JPEG / WebP / GIF）。上传后先当作「常态」，可以在下拉里改成哈气。
- 每张卡片上有「设为常态 / 设为哈气 / 删除」（内置图不能删）。
- 对齐规则：以**常态图的 canvas 宽 + alpha 包围盒**为场景蓝本，每张姿态图按同一个
  「每像素容器宽」渲染，包围盒**水平居中、底边对齐**，高度差的一半作为垂直补偿。
  所以两张图尺寸不同也不会缩放跳变或上下错位。
- 自己上传的图，前端会在本地 canvas 里量一次 alpha 包围盒，并回写给 Host 缓存
  （`POST /maodie/image-meta.json`），下次直接可用。JPEG（没有透明通道）会退化成整张画布。

## 声音 / 闹钟排查（「没声音 / 不响」怎么办）

1. **设置 → 声音** 顶部会把配置问题直接列出来，并给一个**一键启用**按钮：
   - 槽位没勾「启用」、素材池是空的、没有任何槽位绑定 `turn.end` / `alarm.fire`；
   - 「任务完成提醒」总开关或里面的声音开关是关的；
   - 上一次播放失败的原因（例如浏览器的自动播放拦截）。
2. **有两层「声音自愈」，都只认一个东西：你在「提醒」里的意图**
   - **Host 侧（每次启动都会跑，可重复）**：如果「提醒」里声音是**开着**的，却没有任何
     「已启用且勾了素材」的槽位绑在 `turn.end` / `alarm.fire` 上 —— 这就是「通知弹出来了、
     可是没声音」的典型矛盾配置 —— 就把那个「配了素材但没勾启用」的槽位打开
     （一个槽位都没有时补一个默认槽位）。每次修复都追加到 `state.meta.soundHealLog`。
   - **前端侧（交付那一刻，1.2.7 新增）**：投递时如果要求出声（`deliver.sound`）却没有可用槽位，
     页面**当场把配置修好、写回 Host、再播** —— 所以「有弹窗、没声音」不可能再发生。
   - **想彻底静音怎么做**：去「提醒」里关掉那个**声音开关**（那才是意图开关），
     不要靠关槽位的「启用」—— 意图还开着的时候，槽位会被自愈重新打开。
     点猫/三连击这类提示音没有意图开关，它们的槽位「启用」就是你自己的静音开关，不会被自愈碰。
   - 排查：`/maodie/diag` 的 `soundWarnings`（Host 认为哪里不会出声）、`soundHeal`（启动自愈的流水）、
     `frontend.report.soundRepair`（前端在交付时替谁补过配置）。
3. **闹钟的「下次…」在前端本地算**（本机时间、每天/一次性/星期，最多往后看 8 天），
   **每秒自己走**，改完时间立刻反映，不用等 Host 轮询。停用的闹钟会明确写「⏸ 已停用」——
   停用的闹钟**不会响**；**在停用状态下改时间会自动一起启用**（行内会提示）。
   把时间设成「当前这一分钟」会显示「就在这一分钟内」（Host 每 20 秒巡检一次）。
   到点那一分钟如果 Host 的巡检没动静，**前端会替它补一枪**（见坑 №13），所以到点一定响。
4. 设置 → 峰谷里还有**立即测试整条链路**按钮（不用等到点，会走完整的
   「Host 投递 → 前端收 → 冒气泡 + 出声音」流程）。
5. 设置 → 关于显示：SSE 状态、收件箱轮询次数、音频解锁状态、上次播放结果。
6. `http://127.0.0.1:<port>/maodie/diag` 是 Host 侧的全量诊断：
   `indexInjection`（注入行）、`frontend.report`（心跳：SSE / 收件箱 / 音频 / 槽位 / 页面异常）、
   `soundWarnings` + `soundHeal`、`alarms`（本机时间排程）、`session`（本次消耗）、`time`（本地 + 北京）。

> **怎么快速判断「声音到底哪一层断了」**：看 `frontend.report.audio.last`。
> 如果里面是 `ok: true`（比如点击哈气那次成功），说明**浏览器播放链路是好的**，
> 那不出声就一定是**配置层**（槽位没启用 / 没勾素材 / 触发器没绑定）——
> 对照 `soundWarnings` 和 `report.slots` 一眼就能定位。

> **事件是双通道的**：SSE（即时）+ 收件箱轮询（每 5s，`/maodie/inbox.json`）。
> 桌面端主窗口跑在 `dsh-app://` 下时 EventSource 不一定连得上，闹钟/任务完成因此也**丢不了**；
> 两条通道都带 Host 发的 `seq`，前端按 seq 去重，不会重复响。
> `seq` 存在 localStorage，刷新页面不会把已经处理过的闹钟再补一遍。

## 踩过的坑（维护备忘）

1. **老 README 的安装方法已作废**：不要手改 `~/.dsh/profiles/desktop/package.json` 再重启，
   用 `plugin_manager`（应用内 Plugins 页面 / 会话里的工具）。安装本身是热的。
2. **`tapIndex` 对桌面端主窗口无效**：壳直接从 asar 读 dist/index.html，不走 `renderIndex`。
   必须用 `webserver/index-inject` 的结构化注入行。
3. **不要在插件里探测 `electron`**：Host 跑在 Electron 的 Node 子进程里，`require('electron')`   永远失败（`not-electron`）。原生闪烁/系统通知在 Host 侧做不到，交给前端降级
   （页面通知 + 标题闪烁 + 声音 + 气泡）。
4. **注入表只在 Host 启动时收集一次**：新增/删除注入行需要重启桌面端；只改前端脚本不用。
   `/maodie/diag` 的 `indexInjection` + `frontend.booted` 就是用来区分这两件事的。
5. **闹钟按本机时间，峰谷按北京时间**：这是两个不同口径，不要合并。
6. **不要再手写 PowerShell 文本管道改源码**：`Get-Content`/`Set-Content` 在 Windows PowerShell 里
   按 ANSI 码页解码，会把 UTF-8 中文整片毁掉，而且**吞掉奇数长度中文串后面那个 ASCII 字符**
   （引号、逗号都会没），文件直接不再合法。改文件用编辑器 / `node` / 本仓库的 `.build/*.mjs`。
7. **`.build/` 是开发流水线**：`migrate.mjs` + `features.mjs` 重建 `lib/index.js`，
   `front-a.mjs` + `front-b.mjs` 改前端，`prep-tests.mjs` 生成可在 `.build/` 里跑的测试副本。
   先在 `.build/` 里验证再覆盖正式文件，可以避免把坏版本喂给正在运行的 Host。
   `.build/index.v1.0.0.js` 是迁移前的原始 Host 文件备份。
8. **两张猫图尺寸不同**：必须按 alpha 包围盒对齐（见上文），不要直接按画布对齐。
9. **不要再猜 Host 端口**：前端候选基址以「相对路径 / 同源」为第一优先，
   桌面端由 `dsh-app://` 协议处理器转发；绝对基址只作为显式配置时的兜底。
10. **事件序号（seq）只在同一个 Host 进程内可比 —— 这是踩过的血坑**：
   双通道（SSE + 收件箱轮询）靠 seq 去重，最初把 `lastSeq` 也写进了 localStorage。
   Host 一重启，它的计数器从 1 重新开始，可页面还记着旧的大序号（比如 9），
   于是**新事件全被判成「已经处理过」丢掉**：设置里的测试按钮照常弹（那是本地调用、不过 seq），
   真实的任务完成却**什么都不出现**（弹窗和声音一起没）。
   现在：每个 Host 进程有自己的 `bootId`，每条事件和收件箱响应都带 `boot`；
   前端发现 `boot` 变了就**清零 lastSeq**（并立刻用 `since=0` 补拉一次，2 分钟内的事件不丢）；
   `lastSeq` **不再跨页面/跨进程持久化**，基线一律由第一次轮询对齐。
   `test/dom.test.mjs` 里有对应的回归用例（把 `noteBoot` 的重置逻辑关掉，那条就会红）。
   排查口径：`/maodie/diag` 里 `frontend.report.inbox.boot` 应该等于 `events.boot`，
   且 `inbox.lastSeq` 会随 `events.eventSeq` 一起往前走。
11. **不要一边用一边把设置面板重建掉（第二口血坑）**：
   原来的链路是「改控件 → `persist()` → POST `/state.json` → Host 回显 `{type:'state'}`
   → `refreshFromHost()` → `renderAllPanes()`」，也就是**每一次改动都会把每个面板整体重建**。
   于是大概 350ms 后你正在用的那个节点就变成游离节点：原生 `<input type=time>` 的选择器
   和 `<select>` 的下拉会立刻失去宿主 —— 症状就是**「闹钟时间改过一次就输不进去、
   外观的常态/哈气下拉点不开、声音里的『随机』点不开」**（有输入框的都像坏了）。
   现在三条防线：
   - `persist()` 记下 `lastSelfSaveAt`，2.5s 内到达的 `state` 广播判定为**自己的回显**直接忽略；
   - 其它来源的变更走 `requestPaneRender()`：**用户正在操作（刚动过手 / 焦点在 input|select|textarea）时先不重建**，
     记成 pending，每 500ms 重试，等松手再补上；
   - 改时间 / 改启用只 `refreshAlarmTicks()`（只更新「下次…」那行文字），姿态下拉也不再重建自己。
   `test/dom.test.mjs` §12 就是这组回归：先断言「编辑中的节点必须 `isConnected`」，
   再断言「非自己触发的变更仍会同步、但延后重建、松手后补上」。
12. **闹钟的三个坑（1.2.4 修）**：
   - **停用的闹钟永远不会响，而且很难看出为什么**：Host 里 `enabled === false` 直接跳过。
     更糟的是「改时间顺手启用」原本用 `confirm()` 问一句 —— 弹窗被点掉、或者被上面第 11 条
     的面板重建吞掉，就留下一个**看起来配好了、却永远不会响**的闹钟。
     现在：**在停用状态下改时间 = 直接启用**，行内会提示「已随改时间自动启用」。
   - **「就在这一分钟」被当成已经过去了**：原来的判据是 `目标时刻 > now`，所以把时间设成
     当前这一分钟（秒数已经走了一点）就会显示成**明天** —— 看着就像「设了个时间它直接跨过去了」。
     现在按**分钟**比较：当前这一分钟算「现在就到」，显示「就在这一分钟内，Host 每 20 秒巡检一次」。
   - **时间字符串全等比较**：`"5:28"` 和 `"05:28"` 不等，一个格式差异就让它永远不匹配。
     现在统一归一化成 `HH:MM` 再比（`"8:15"` / `"08:15"` / `"08:15:00"` 都行）。
   排查口径：`/maodie/diag` 的 `alarmChecks` 是**最近一次 20 秒巡检**的记录
   （它当时算出的 `hhmm`、以及这一轮触发了哪些闹钟），`alarms` 是每个闹钟的 `enabled` / `nextAt` / `nextIn`。
   这两块一看就知道是「没启用」「时间格式不匹配」还是「排程跳到了明天」。
13. **闹钟到点不响的真正元凶：那个 20 秒巡检从来没跑过（1.2.6 修）**：
   现场证据是 `/maodie/diag` 里 **`alarmChecks` 一直是 `null`** —— 巡检函数一次都没被调用。
   原因：定时器是用 `ctx.setInterval(...)` 注册的，外面套了 `try/catch` 而 **catch 里什么都不做**，
   注册一旦失败就**静默地没有定时器**。而「立即测试整条链路」走的是 `deliverAlarm()` 直接投递，
   根本不经过巡检 —— 于是现象就是「测试通、到点永远不响」。四条修改：
   - 定时器改用 **Host 进程自己的全局 `setInterval`**（语义最确定），并把
     `timers` / `timerTicks` / `timerErrors` 记进 `diag` —— 以后「没在跑」是看得见的，不会再静默失败。
   - `/maodie/diag?runAlarmSweep=1` 可以**手动跑一次巡检**（诊断和测试都用它，不用再等 20 秒）。
   - 投递收敛成**唯一入口** `fireAlarmOnce(alarm, isTest)`，按「闹钟 + 分钟」幂等：
     巡检、手动、前端兜底同时动作也**只响一次**。
   - 新增 `POST /maodie/alarm-fire.json {id}`：投递指定闹钟（停用则拒投、不存在则 404）。
   - **前端兜底**：页面自己也盯时钟（每 3 秒一轮）。到点那一分钟如果到 `:25` 还没收到 Host 的
     `alarm` 事件，就 `POST /alarm-fire.json` 把 Host「叫醒」。前端**不自己出声**，
     只走 Host 那条投递链路，所以不会重复响 —— 即使 Host 定时器再次静默死掉，闹钟照样会响。
   排查口径（三层一次看全）：
   | 看什么 | 含义 |
   | --- | --- |
   | `timers` / `timerTicks.alarm` | 巡检定时器有没有登记、**跑了几次**（应每 20 秒 +1） |
   | `alarmChecks.hhmm` / `.fired` | 最近一次巡检算的是哪一分钟、触发了谁（一直 `null` = 巡检没跑） |
   | `frontend.report.alarmWatch.pokes` | 前端替 Host 补过枪（非空说明 Host 侧那时没动静） |
14. **「通知弹出来了、可是没声音」为什么会复发（1.2.7 修）**：
   1.2.1 的自愈用 `state.meta.soundAutoHealed[trigger]` 记「这个触发器修过了、以后不再碰」。
   现场证据：`slot-done`（`turn.end`）**又被关掉了**，而那条记录还写着 `{turn.end: …}` ——
   于是**记录本身挡住了后续所有修复**，弹窗照旧、声音永远没有，界面上还显示「已经修过了」。
   两处修改：
   - Host 的自愈改成**可重复**（去掉 `soundAutoHealed` 的闸门），只认「提醒」里的意图；
     每次修复追加到 `state.meta.soundHealLog`（保留最近 10 条）。
   - **交付时自愈**（前端）：`fireTrigger(trigger, {intent:true})` 时如果没有可用槽位，
     当场把「配了素材但没勾启用」的槽位打开 / 补默认素材池 / 新建默认槽位，`persist()` 写回 Host，
     **然后照常播**。所以「有弹窗、没声音」这条路被彻底堵死了。
   - **缺省即「要声音」**（1.2.9 补）：状态文件里根本没有 `notify` 这一段时，投递侧本来就
     当成开着，自愈也必须同样判断 —— 否则会误判成「用户不要声音」而袖手旁观。
   - **静音的正确表达**：关掉「提醒」里的**声音开关**（意图）；不要靠关槽位的「启用」——
     意图还开着时它会被自愈打开。点猫/三连击没有意图开关，它们的「启用」就是用户的静音开关，
     自愈**不会**去碰（dom 测试里正反两面都断言了）。
   | 看什么 | 含义 |
   | --- | --- |
   | `soundWarnings` | Host 认为哪些触发器不会出声（矛盾配置清单） |
   | `soundHeal` / `state.meta.soundHealLog` | 启动自愈修了什么、什么时候修的（流水） |
   | `frontend.report.soundRepair` | 前端在**交付那一刻**替谁补过配置（非空=刚好撞上矛盾配置） |
15. **设置窗口不再可拖动（1.2.9，用户要求）**：原来标题栏能拖着走并写 inline `left/top`，
   拖到屏幕边缘/被别的界面盖住之后就很难拉回来（用户反馈「设置卡到那个页面上面了」）。
   现在：拖动逻辑整块删掉，窗口**固定居中**，并且每次打开（含复用已存在的窗口时）都会清掉
   残留的 inline 位置 —— 所以已经卡住的窗口，加载新版后一打开就自动回到中间。
   标题栏光标也从 `cursor:move` 改成普通箭头。回归用例断言「重开会清掉残留位置」和
   「拖标题栏不再移动窗口」。

## 仓库与版本

这个目录本身就是一个 Git 仓库（`main` 分支，标签 `v1.2.9`）。

- **权威文件**：`lib/index.js`（Host 侧）与 `assets/maodie.js`（前端）。只有改这两个才算改了插件。
- `.build/` 是**开发流水线**：每一步修复一个脚本（脚本注释里写了当时的现场、根因和取舍），
  外加迁移前的两个原件 `index.v1.0.0.js` / `frontend.v1.0.0.js`。
  它是**修改记录**，不保证能从 1.0.0 一键重放（最早那一版前端迁移脚本没有留下）。
  生成物 `.build/index.js`、`.build/frontend.js` 以及复制出来的测试文件已被 `.gitignore` 忽略。
- 本机安装状态不在仓库里：profile 的 junction（`~/.dsh/profiles/desktop/node_modules/maodie`）、
  运行时数据（`~/.dsh/maodie/`）都各自独立。

保存一次改动：

```powershell
git add -A
git commit -m "这次改了什么"
git tag -a v1.2.10 -m "一句话"     # 版本号与 package.json / PLUGIN_VERSION / MAODIE_VERSION 保持一致
```

推到远端（先在网页上建一个空仓库）：

```powershell
git remote add origin https://github.com/<用户名>/dsh-maodie.git
git push -u origin main --tags
```
